# 策略选择持久化修复

目标：任务选项中选择作战策略后，重新启动程序仍恢复同一策略。

根因：TaskOptionGenerator 的实际下拉框选择事件只写 Index，未调用 StrategyOptionProvider.RememberSelectedCase；TaskLoader 的启动恢复依赖 data 中的策略标识，无标识时按安全策略回退默认。旧 TaskQueueView 的同类方法虽有标识保存，但当前面板由 TaskOptionGenerator 生成。

范围：在实际选择事件中同步保存稳定策略标识，不改其他选项；保留目录重排按标识恢复、标识缺失或策略删除时回退默认的规则。不根据已被重置的索引猜测用户此前选择。

- [x] 使用实际下拉控件和配置转换器复现保存、重新加载、目录重排导致选择丢失。
- [x] 修复实际控件选择事件，验证普通选项不受影响。
- [x] 执行完整测试、审查并更新用户使用的 win-x64 发布目录。

约束：中文注释，保留用户配置和策略文件，不执行真实游戏操作。

测试进展：首次真实控件测试因缺少主视图模型服务而失败；加入测试范围内的空闲状态服务并在结束后恢复。修复前策略持久化的 3 个选择用例均失败，普通选项用例通过，确认缺失的是策略标识写入。

验证结果：完整 Release 测试 116 项通过。独立审查确认实际事件、配置转换器和恢复流程衔接正确，测试缓存恢复完整。win-x64 发布成功，构建和发布核心程序的 SHA256 一致，default.json 的 SHA256 构建前后一致。未执行真实 exe 重启；已被旧版本覆盖的选择需用户重新选择一次。
